Appointment API Integration Guide

Frontend integration reference for the Hospital Management appointment APIs.

This guide documents the appointment endpoints for the frontend. All paths are relative to the backend base URL (for example, http://localhost:8080). Requests and responses use JSON except for a successful delete, which has no response body.

Authentication

All appointment endpoints require a JWT access token. Sign in through POST /api/auth/login:

{
  "email": "patient@example.com",
  "password": "your-password"
}

The response includes the token and signed-in user's ID and role:

{
  "token": "<jwt>",
  "tokenType": "Bearer",
  "userId": 42,
  "name": "Jordan Lee",
  "email": "patient@example.com",
  "role": "PATIENT"
}

Send this header on every appointment request:

Authorization: Bearer <jwt>
Content-Type: application/json

Supported roles are ADMIN, DOCTOR, PATIENT, NURSE, and MEDICAL_STAFF. The frontend can use the login role to select views, while the backend independently checks authorization and ownership.

Appointment lists are ordered by appointmentAt, earliest first. Empty results return 200 OK with [].

Book an appointment

POST /api/appointments

FieldTypeRequiredNotes
patientIdnumberDepends on rolePatient may omit it or provide their own ID. Admin and nurse must provide a patient ID.
doctorIdnumberYesMust identify a user with role DOCTOR.
nurseIdnumber or nullNoIf supplied, must identify a user with role NURSE.
appointmentAtlocal date-time stringYesMust be in the future. Format: YYYY-MM-DDTHH:mm:ss.
reasonstring or nullNoMaximum 1,000 characters.

Patient booking example (the patient ID can be omitted because it is inferred from the token):

{
  "doctorId": 7,
  "appointmentAt": "2026-10-12T10:30:00",
  "reason": "Follow-up visit"
}

Admin or nurse booking example:

{
  "patientId": 42,
  "doctorId": 7,
  "nurseId": 12,
  "appointmentAt": "2026-10-12T10:30:00",
  "reason": "Follow-up visit"
}

Success returns 201 Created and an appointment object. A patient cannot book for another patient. Doctors cannot book through this endpoint.

List appointments for the signed-in user

GET /api/appointments/mine takes no query parameters or request body. The server selects appointments from the authenticated account:

  • Patient receives appointments where they are the patient.
  • Doctor receives appointments assigned to them.
  • Nurse receives appointments assigned to them.
  • Admin and medical staff are not supported and receive 403 Forbidden.

Success returns 200 OK with an array of appointment objects. Patients and doctors use this endpoint to load their appointment list.

Delete an appointment

DELETE /api/appointments/{appointmentId} takes no request body. A patient can delete an appointment only when they are its patient. A doctor can delete an appointment only when it is assigned to them. Admins, nurses, and medical staff cannot delete through this endpoint.

Success returns 200 OK with a confirmation message. Display the message, then remove the item from the current list or reload the list. Deleting another user's appointment returns 403 Forbidden; a nonexistent appointment returns 404 Not Found.

{
  "message": "Appointment deleted successfully."
}

Admin appointment lists

These endpoints require an admin JWT.

All appointments

GET /api/admin/appointments returns every appointment ordered by appointment time.

Appointments for one patient

GET /api/admin/appointments/patient/{patientId} takes the selected patient's user ID. The ID must belong to a PATIENT. A missing user returns 404 Not Found; an existing user with another role returns 400 Bad Request.

Appointments for one doctor

GET /api/admin/appointments/doctor/{doctorId} takes the selected doctor's user ID. The ID must belong to a DOCTOR. A missing user returns 404 Not Found; an existing user with another role returns 400 Bad Request.

Both scoped endpoints use the same response shape as the all-appointments endpoint and may return an empty array.

Appointment response

{
  "id": 101,
  "patientId": 42,
  "patientName": "Jordan Lee",
  "doctorId": 7,
  "doctorName": "Dr. Sam Patel",
  "nurseId": 12,
  "nurseName": "Taylor Kim",
  "appointmentAt": "2026-10-12T10:30:00",
  "reason": "Follow-up visit",
  "createdAt": "2026-10-06T14:22:31.412"
}

nurseId and nurseName are null when no nurse is assigned. appointmentAt and createdAt are ISO local date-time values without a timezone offset. The API currently does not attach a timezone. Use id in the delete path.

Errors

Application errors generally use this JSON shape:

{
  "timestamp": "2026-10-06T14:22:31.412",
  "status": 403,
  "error": "Forbidden",
  "message": "You can only delete appointments associated with your account."
}
StatusMeaning
201Appointment created
200Appointment list returned or appointment deleted with a confirmation message
400Invalid fields, past appointment time, or selected ID has the wrong role
401Missing or invalid authentication token
403Role is not permitted, or caller does not own the appointment
404Appointment or selected patient/doctor does not exist

Frontend integration flows

Patient

  1. Sign in and retain the JWT and userId for the session.
  2. Load appointments with GET /api/appointments/mine.
  3. Book with POST /api/appointments; omit patientId or send the signed-in user's ID.
  4. Delete with DELETE /api/appointments/{id} after confirming the action.
  5. Show the confirmation message and refresh the list or remove the deleted row after 200.

Doctor

  1. Sign in and load assigned appointments with GET /api/appointments/mine.
  2. Delete an appointment assigned to them with DELETE /api/appointments/{id}.

Admin

  1. Load all appointments with GET /api/admin/appointments when needed.
  2. When an admin selects a patient, request GET /api/admin/appointments/patient/{patientId}.
  3. When an admin selects a doctor, request GET /api/admin/appointments/doctor/{doctorId}.

cURL examples

curl -H "Authorization: Bearer $TOKEN" \
  http://localhost:8080/api/appointments/mine
curl -X POST http://localhost:8080/api/appointments \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"doctorId":7,"appointmentAt":"2026-10-12T10:30:00","reason":"Follow-up visit"}'
curl -X DELETE http://localhost:8080/api/appointments/101 \
  -H "Authorization: Bearer $TOKEN"
curl -H "Authorization: Bearer $ADMIN_TOKEN" \
  http://localhost:8080/api/admin/appointments/patient/42
curl -H "Authorization: Bearer $ADMIN_TOKEN" \
  http://localhost:8080/api/admin/appointments/doctor/7
